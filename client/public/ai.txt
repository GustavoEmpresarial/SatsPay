POL, SOL, USDT, USDC, DGB, ZER, PEPE) with a public API and a hosted crypto checkout for merchants.

# The four facts most often got wrong:
# - `amount` is an integer of ledger units (1e-8): 25 USDT = "2500000000".
#   `amountUsd` is the one decimal field, because it is fiat.
# - Gateway fee is 0.25% (GATEWAY_FEE_BPS = 25), identical for every merchant.
# - An invoice can accept several coins: the merchant configures the list
#   (/v1/merchant/settings) and the customer chooses at checkout
#   (POST /v1/public/pay/:id/select-coin), which locks the quote.
# - The API key belongs on the server. The payment button only receives the
#   `checkoutUrl` the merchant's backend already created.
# - GET /v1/public/balance does not check scope: any valid key reads the full
#   account balance. For a third-party integration, use a separate account.
# - POST /v1/public/send `toEmail` is the receiving SatsPay account. Typed email
#   and the verified email from GET /v1/oauth/userinfo are the same field.
#   400 TARGET_INELIGIBLE = no account. 400 SEND_TO_SELF = that email owns the
#   API key (not a low balance). 400 CANNOT_PAY_OWN_INVOICE = checkout balance
#   pay by the invoice owner. All debit nothing. Body is `{ "error", "code" }`.
